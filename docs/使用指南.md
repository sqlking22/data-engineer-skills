## 快速开始

### 环境准备

1. **安装Claude Code**
   ```bash
   # 确保已安装Claude Code CLI
   claude --version
   ```

2. **安装技能套件**
   ```bash
   # 方式1：全局安装
   cp -r data-engineer-skills ~/.claude/skills/
   
   # 方式2：项目级安装
   cp -r data-engineer-skills /your/project/.claude/skills/
   ```

3. **验证安装**
   ```bash
   # 启动Claude Code
   claude
   
   # 测试命令
   /requirement-analyst 测试需求分析
   ```

### 第一个示例

```bash
# 5分钟完成一个简单的数据开发任务

# 步骤1：需求分析
/requirement-analyst 分析需求：统计每日订单量和销售额

# 步骤2：数据建模
/modeling-assistant 设计订单事实表模型

# 步骤3：SQL开发
/sql-assistant 使用MaxCompute语法生成日销售统计SQL

# 步骤4：质量规则
/dq-assistant 为订单表建立质量监控

# 步骤5：生成测试
/test-engineer 生成订单数据测试用例
```

## 需求分析助手

### 概述

将模糊的业务需求转化为结构化的技术规格，为后续建模和开发提供清晰输入。

### 核心功能

| 功能 | 命令 | 说明 |
|------|------|------|
| 需求解析 | `/requirement-parser` | 提取业务实体、指标、维度 |
| 需求澄清 | `/requirement-clarify` | 识别缺失信息，生成确认问题 |
| 需求转化 | `/requirement-transform` | 转化为技术规格 |

### 使用方式

#### 方式1：端到端工作流

```bash
/requirement-analyst 分析电商销售分析需求：
- 业务目标：统计各区域销售额和订单量
- 数据源：订单表、用户表
- 分析维度：日期、区域、品类
```

#### 方式2：分阶段执行

```bash
# 阶段1：解析需求
/requirement-parser 提取需求中的实体和指标

# 阶段2：澄清需求
/requirement-clarify 识别需求缺口

# 阶段3：转化为技术规格
/requirement-transform 输出技术规格文档
```

### 输出格式

需求分析输出标准化的 `requirement_package.yaml`：

```yaml
requirement_package:
  version: "1.0"
  metadata:
    project_name: "电商销售分析"
    generated_by: "requirement-analyst"
    generated_at: "2024-01-15T10:00:00Z"

  business:
    domain: "电商"
    goal: "销售数据分析"

  functional:
    entities:
      - name: "订单"
        attributes: ["订单ID", "用户ID", "金额", "时间"]
      - name: "用户"
        attributes: ["用户ID", "姓名", "城市"]

    metrics:
      - name: "销售额"
        formula: "SUM(订单金额)"
      - name: "订单量"
        formula: "COUNT(订单ID)"

    dimensions:
      - name: "日期"
      - name: "区域"
      - name: "品类"

  non_functional:
    freshness: "T+1"
    retention: "3年"
    accuracy: "99.9%"

  downstream_specs:
    - target: "modeling-assistant"
      input_file: "requirement_package.yaml"
```

### 最佳实践

1. **提供充分上下文**
   ```
   ✅ 好的需求描述：
   分析电商销售数据，数据源是订单表（日增10万条）和用户表（100万用户），
   需要统计各区域的销售额、订单量，目标是T+1时效，使用MaxCompute数仓。
   
   ❌ 不好的需求描述：
   帮我分析销售数据
   ```

2. **确认关键信息**
   - 数据源和表结构
   - 业务指标定义
   - 数据量和时效要求

3. **利用输出包**
   - 传递给建模助手设计模型
   - 作为项目的需求文档

## 数据建模助手

### 概述

设计维度模型，定义事实表和维度表结构，输出Schema设计。

### 核心功能

| 功能 | 命令 | 说明 |
|------|------|------|
| 模型设计 | `/model-design` | 维度建模设计 |
| Schema文档 | `/schema-doc` | 生成数据字典 |

### 使用方式

#### 方式1：基于需求包建模

```bash
/modeling-assistant 基于 requirement_package.yaml 设计维度模型
```

#### 方式2：直接建模

```bash
/modeling-assistant 设计电商订单模型：
- 业务流程：订单销售
- 分析需求：销售趋势、用户消费分析
- 数据源：订单表、用户表、商品表
- 数据量：日增10万订单
```

### 输出格式

建模输出标准化的 `modeling_package.yaml`：

```yaml
modeling_package:
  version: "1.0"
  metadata:
    project_name: "电商数据仓库"
    generated_by: "modeling-assistant"

  fact_tables:
    - name: "fct_orders"
      grain: "订单级别"
      description: "订单事实表"
      dimensions:
        - dim_date
        - dim_user
        - dim_product
      measures:
        - name: "quantity"
          type: "integer"
          description: "数量"
        - name: "amount"
          type: "decimal(18,2)"
          description: "金额"

  dimensions:
    - name: "dim_user"
      type: "SCD Type 1"
      natural_key: "user_id"
      attributes:
        - name: "user_id"
          type: "BIGINT"
        - name: "username"
          type: "VARCHAR(100)"
        - name: "city"
          type: "VARCHAR(50)"

  schemas:
    fct_orders:
      columns:
        - name: "order_id"
          type: "BIGINT"
          primary_key: true
        - name: "user_id"
          type: "BIGINT"
          foreign_key: "dim_user.user_id"
        - name: "order_time"
          type: "DATETIME"
        - name: "amount"
          type: "DECIMAL(18,2)"
```

### 建模最佳实践

1. **粒度设计原则**
   - 事实表粒度应是最细的业务级别
   - 同一事实表的所有度量必须在相同粒度

2. **维度设计原则**
   - 维度表应包含丰富的描述属性
   - 根据业务需求选择SCD策略

3. **命名规范**
   - 事实表：`fct_` 前缀
   - 维度表：`dim_` 前缀
   - 聚合表：`agg_` 前缀

## SQL智能开发助手

### 概述

生成、审查、优化SQL代码，支持多种数据库方言。

### 核心功能

| 功能 | 命令 | Agent | 说明 |
|------|------|-------|------|
| SQL生成 | `/sql-gen` | general-purpose | 自然语言转SQL |
| SQL审查 | `/sql-review` | Explore | 代码质量审查 |
| 执行计划分析 | `/sql-explain` | Explore | 性能瓶颈诊断 |

### 使用方式

#### 功能1：SQL生成

```bash
# 基本用法
/sql-gen 使用MaxCompute语法，查询过去7天每天的新增用户数

# 复杂查询
/sql-gen 使用ADB MySQL语法，统计各区域销售额：
         按日期和区域分组，显示销售额、订单量、客单价
         要求计算环比增长

# 基于模型生成DDL
/sql-assistant 基于 modeling_package.yaml 生成建表DDL
```

#### 功能2：SQL审查

```bash
# 审查SQL代码
/sql-review
SELECT * FROM orders WHERE status = 'completed'

# 审查文件中的SQL
/sql-review queries/report.sql
```

#### 功能3：执行计划分析

```bash
# 分析执行计划（需要实际执行EXPLAIN）
/sql-explain
[粘贴EXPLAIN输出结果]
```

### 数据库支持

#### MaxCompute

```sql
-- 特有语法示例
SELECT /*+ MAPJOIN(dim_user) */
    o.order_id,
    u.username
FROM orders o
JOIN dim_user u ON o.user_id = u.user_id;

-- 分区表查询
SELECT * FROM orders
WHERE pt = '202401' AND dt = '01';
```

#### AnalyticDB MySQL

```sql
-- 特有语法示例
CREATE TABLE orders (
    order_id BIGINT NOT NULL,
    order_time DATETIME NOT NULL,
    PRIMARY KEY (order_id, order_time)
)
DISTRIBUTED BY HASH(order_id)
PARTITION BY VALUE(DATE_FORMAT(order_time, '%Y%m'));
```

### SQL生成前置检查

```markdown
【强制】SQL生成前必须确认：
- [ ] 数据库类型（MaxCompute/ADB MySQL）
- [ ] 表结构信息（有DDL或样本数据）
- [ ] 查询目的（OLAP分析/数据导出）
```

## 数据质量检查助手

### 概述

建立数据质量监控体系，生成质量规则和检查报告。

### 核心功能

| 功能 | 命令 | 说明 |
|------|------|------|
| 规则生成 | `/dq-rule-gen` | 基于表结构生成质量规则 |
| 质量检查 | `/dq-check` | 执行质量检查并生成报告 |
| 数据字典 | `/dq-doc` | 生成数据字典 |

### 使用方式

```bash
# 基于表结构生成质量规则
/dq-rule-gen 为订单表生成质量规则：
- 字段：order_id, user_id, amount, status, created_at
- 业务要求：金额必须为正数，状态只能是pending/completed/cancelled

# 执行质量检查
/dq-check 对订单表执行质量检查

# 生成数据字典
/dq-doc 生成订单表的完整数据字典
```

### 输出格式

```yaml
dq_package:
  version: "1.0"
  metadata:
    target_table: "orders"
    generated_by: "dq-assistant"

  rules:
    - name: "order_id_not_null"
      column: "order_id"
      rule_type: "not_null"
      severity: "error"

    - name: "amount_positive"
      column: "amount"
      rule_type: "range"
      params:
        min: 0
        max: 10000000
      severity: "error"

    - name: "status_valid"
      column: "status"
      rule_type: "enum"
      params:
        values: ["pending", "completed", "cancelled"]
      severity: "error"

  data_dictionary:
    - column: "order_id"
      type: "BIGINT"
      description: "订单唯一标识"
      quality_rules: ["not_null", "unique"]
```

### 质量规则类型

| 规则类型 | 说明 | 示例 |
|---------|------|------|
| `not_null` | 非空检查 | order_id不能为空 |
| `unique` | 唯一性检查 | 订单号唯一 |
| `range` | 范围检查 | 金额在0-100万之间 |
| `enum` | 枚举值检查 | 状态只能是指定值 |
| `pattern` | 格式检查 | 手机号格式 |
| `custom` | 自定义规则 | 业务逻辑检查 |

## 数据测试工程师

### 概述

生成数据测试用例，验证数据质量和业务逻辑正确性。

### 核心功能

| 功能 | 命令 | 说明 |
|------|------|------|

### 使用方式

```bash
# 基于质量规则生成测试
/test-engineer 基于 dq_package.yaml 生成单元测试

# 生成集成测试
/integration-test 验证订单数据从ODS到DWD的转换正确性

```

```yaml

    passed: 14
    failed: 1
    coverage: 92.5%
```

## 工作流联动

### 完整工作流

```bash
# 一条命令完成所有阶段
/skill-hub 端到端建设电商销售分析数仓
```

### 分步工作流

```bash
# 步骤1：需求分析
/requirement-analyst 分析电商销售需求

# 步骤2：建模（基于需求包）
/modeling-assistant 基于 requirement_package.yaml 设计模型

# 步骤3：SQL开发（基于模型）
/sql-assistant 基于 modeling_package.yaml 生成DDL

# 步骤4：质量规则（基于模型）
/dq-assistant 基于 modeling_package.yaml 生成质量规则

# 步骤5：测试（基于质量规则）
/test-engineer 基于 dq_package.yaml 生成测试用例
```

### 工作流选择

| 场景 | 推荐工作流 |
|------|-----------|
| 新项目从零开始 | 完整工作流（5阶段） |
| 已有模型，生成SQL | 建模→SQL |
| 已有SQL，建立质量 | SQL→质量 |
| 质量规则到测试 | 质量→测试 |
| 快速原型开发 | SQL→质量→测试 |

## 常见问题

### Q1: Skill命令不触发？

```bash
# 检查skill目录
ls ~/.claude/skills/data-engineer-skills/

# 检查SKILL.md格式
head -20 ~/.claude/skills/data-engineer-skills/SKILL.md

# 重启Claude Code
```

### Q2: 生成的SQL不符合预期？

- 确认数据库类型是否正确指定
- 提供更详细的表结构信息
- 分步骤生成复杂查询

### Q3: 模块联动失败？

- 检查输出包文件是否正确生成
- 确认`skill-connections.yaml`配置
- 使用 `--from-xxx` 参数显式指定上游输入

### Q4: 如何定制规则？

修改各模块的references目录下的规范文档：
- `sql-assistant/references/sql-standards.md` - SQL规范
- `dq-assistant/references/data-quality-standards.md` - 质量规则
